## 一、项目概述

**寻旅记** 是一款以"打卡即发布"为核心机制的旅行社区 App。用户浏览路线/攻略/打卡地 → 加入行程 → AI 智能排序 → GPS 打卡 → 内容自动沉淀至社区流，形成"工具+社区"双轮驱动的闭环。

**核心特色**：
- 打卡即发布：一次打卡同时完成内容生产与行程记录
- AI 三件套：行程规划 + 个性化推荐 + 预算超支提醒
- CPS 分销：P0 只接高德打车（交通）+ 饿了么（吃喝），零库存变现；携程/美团推至 P1
- GPS 定位三模式：计划模式 / 旅行模式 / 手动模式

**当前状态**：产品文档 21 份 + 高保真原型 v2.1.7 已完成，待进入代码开发阶段。

## 四、数据模型概览

数据库共 **36 张表**，核心表如下：

| 模块 | 核心表 | 说明 |
|------|--------|------|
| 用户 | user, user_oauth, user_setting, role, user_role | 用户基础信息、第三方账号、隐私设置、角色权限 |
| 内容 | place, checkin_record, route, route_point, guide | 打卡地、打卡记录（统一表）、路线、路线点位、攻略 |
| 行程 | trip, trip_point, route_transport | 行程、行程点位（4Tab 数据源）、行程交通 |
| 社交 | comment, comment_like, follow, favorite, message | 评论、评论点赞、关注、收藏、消息 |
| 互动 | tip_vote, guide_question, guide_answer, guide_answer_like, report | 避雷点赞、攻略问答（提问+回答）、回答点赞、举报 |
| AI | ai_chat_session, ai_chat_message | AI 对话会话、对话消息 |
| 成就 | badge_definition, user_badge, user_medal_summary | 勋章定义、用户勋章、勋章汇总（P1） |
| 地图 | city, user_city_progress, user_province_progress, user_national_ranking | 城市、用户城市/省份进度、全国排名（P1） |
| 系统 | creator_application, audit_log | 创作者认证、审计日志 |

**关键设计**：`checkin_record` 为统一内容表，`source` 字段区分来源（行程打卡 / 主动发布），`content_richness` 字段分级（轻量 / 标准 / 丰富）影响分发权重。

### P0 核心闭环（当前开发目标）

```
浏览路线/攻略/打卡地 → 加入行程 → AI 智能排序 → GPS 打卡 → 内容沉淀至社区流
     ↑                                                        ↓
     └──────────── 个性化推荐 ← 用户行为画像 ←──────────────────┘
```

**P0 功能模块**（按开发优先级排序）：
1. 全局基础（8 项）：底部导航、顶部栏、语言切换、城市选择、页面跳转、交互反馈
2. 用户系统（含登录注册、JWT 鉴权）
3. 内容服务（首页 5 Tab（关注/附近/推荐/攻略/打卡地/路线）、路线/打卡地/攻略详情、搜索）
4. 行程管理（行程 CRUD、行程详情 4Tab、打卡即发布）
5. 社交互动（关注、点赞、评论、收藏、消息）
6. 发布机制（6 大分类、通用+专属模板、图片上传）
7. AI 能力（对话式规划行程、个性化推荐算法、预算超支提醒）
8. 定位功能（GPS 三模式、发布打卡地定位、打卡 GPS 验证）
9. CPS 分销（P0：饿了么/高德打车；P1：携程/美团）

### 首发城市与冷启动策略

**首发城市**（维持 3 城）：
- **荆州**：老板本地人，拥有本地校园流量资源（长江大学等高校），荆州是文旅重点城市、高校不少，可与荆州市文旅局对接合作争取智慧旅游补贴。
- **武汉**：湖北省会，高校密集、年轻用户基数大。
- **宜昌**：三峡旅游门户，旅游场景丰富。

**冷启动策略**（v2.1.7 决策更新）：
- 暂不批准 KOL 预算，采用「AI 生成内容 + 种子用户自然增长」方案。
- 上线前：运营侧使用 AI 生成约 500 篇城市攻略（荆州/武汉/宜昌各约 170 篇），人工校准门票、开放时间、价格等核心数据；官方团队填充样板路线和打卡地数据。
- 上线后：通过老板校园资源引入种子用户自然增长，举办"最有帮助的避雷王"评选激发早期活跃度。
- 详见 04_运营与合规手册.md「冷启动策略」。

## 十、开发推进建议

### 使用 TRAE Code 模式的最佳实践

1. **先建后端骨架**：让 TRAE 先生成项目结构、配置加载、中间件，再逐步填充业务逻辑
2. **按模块推进**：每完成一个 Step 的全部接口开发与测试后再进入下一个 Step
3. **文档驱动开发**：每开发一个模块前，先把对应的文档内容提供给 TRAE 作为上下文
4. **原型对照**：前端开发时始终对照 `寻旅记v2.1.7.html` 原型，确保视觉与交互一致
5. **增量测试**：每完成一个接口就用 Postman/Apifox 测试，不要堆积到最后联调

### 每步开发的通用流程

```
阅读对应文档 → 提供 TRAE 上下文 → 生成代码 → 本地测试 → 修复 → 进入下一步
```
