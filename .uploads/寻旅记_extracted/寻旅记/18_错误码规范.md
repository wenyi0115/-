# 寻旅记 · 错误码规范

> 版本：v2.1.7 | 日期：2026年6月 | 状态：正式版

---

## 一、通用返回格式

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 0=成功，非0=错误 |
| message | string | 人类可读的描述 |
| data | object | 业务数据，错误时为 null |
| request_id | string | 请求追踪 ID，用于日志排查 |

---

## 二、错误码分段规则

```
1xxx — 通用错误
2xxx — 认证与授权
3xxx — 用户相关
4xxx — 内容相关（地点/路线/攻略/打卡）
5xxx — 行程相关
6xxx — 社交相关（评论/关注/收藏/点赞）
7xxx — 文件上传
8xxx — AI 服务（含豆包 API、内容审核、排序、规划、识别、额度）
9xxx — 系统错误
```

**扩展段位（5 位错误码，用于第二阶段及以后新增模块）**：

```
15000-15099 — CPS 分销相关
16000-16099 — 定位相关
18000-18099 — 行程工具相关（清单/账单/地图/天气）
```

> **说明**：扩展段位采用 5 位编码，与基础 4 位段位（1xxx-9xxx）并行使用，避免与既有错误码冲突。前端处理策略保持一致，按错误码区间匹配对应处理逻辑。

## 四、前端错误处理策略

### 4.1 全局拦截器

```
- 2001/2002/2003：清除本地 Token，跳转登录页
- 2005：弹出「账号已被封禁」提示，强制退出
- 1006/9007：显示「操作频繁，请稍后重试」
- 9001/9002/9006：显示「网络开小差了，请稍后重试」
- 1009/9008：显示「服务维护中，预计 X 分钟恢复」
- 其他 4xx：Toast 显示 message 字段内容
- 其他 5xx：Toast 显示「服务异常，请稍后重试」
```

### 4.2 Toast 显示规则

| 场景 | 显示方式 | 时长 |
|------|----------|------|
| 操作成功 | 绿色 Toast | 2 秒 |
| 提示信息 | 灰色 Toast | 2 秒 |
| 操作失败 | 警示红 Toast | 3 秒 |
| 网络错误 | 警示红 Toast | 3 秒 |
| 升级提示 | 模态弹窗 | 用户手动关闭 |

### 4.3 离线降级

| 功能 | 离线行为 |
|------|----------|
| 浏览首页 | 展示缓存数据，顶部显示"离线模式" |
| 查看详情 | 展示缓存数据 |
| 打卡 | 本地暂存，恢复网络后自动同步 |
| 发布内容 | 提示"发布需要网络连接" |
| 搜索 | 提示"搜索需要网络连接" |

## 五、错误码添加流程

1. 开发者在对应模块预留错误码
2. 确认错误码未被占用（查表）
3. 在代码中注册错误码和 message
4. 更新本文档
5. 通知前端同步更新错误处理

## 六、与 API 文档的对应关系

本文档与 `06_API接口文档.md` 中的错误码保持同步。API 文档中每个接口列出了可能返回的具体错误码，本文档为错误码的完整定义和前端处理策略。

**同步规则**：API 文档接口中新增错误码时，必须同步更新本文档的对应章节。
