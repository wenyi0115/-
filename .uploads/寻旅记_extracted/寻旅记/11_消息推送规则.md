## 一、概述

### 1.1 设计目标

寻旅记消息推送体系旨在实现以下目标：

- **精准触达**：确保关键信息（行程提醒、账号安全）第一时间送达用户
- **体验友好**：避免过度推送造成骚扰，支持用户自定义推送偏好
- **多端覆盖**：同时覆盖 iOS、Android 和微信小程序三端推送通道
- **可量化**：通过埋点数据持续优化推送策略和转化率

### 1.2 推送通道总览

| 端 | 主通道 | 备用通道 | 厂商通道 |
|----|--------|----------|----------|
| iOS | APNs (Apple Push Notification service) | 长连接 WebSocket | -- |
| Android | FCM (Firebase Cloud Messaging) | 长连接 WebSocket | 华为 / 小米 / OPPO / vivo |
| 微信小程序 | 订阅消息 | 服务通知 | -- |

## 二、推送类型分类

### 2.1 系统通知（System Notification）

系统通知属于平台级消息，强制推送，用户不可关闭。

| 子类型 | 触发条件 | 推送对象 | 示例场景 |
|--------|----------|----------|----------|
| 审核结果 | 管理员审核通过/驳回 | 内容发布者 | 路线审核通过、笔记审核驳回 |
| 账号安全 | 异地登录、密码修改、设备绑定 | 账号持有者 | 新设备登录提醒、密码已修改 |
| 版本更新（强制） | 新版本发布且不兼容旧版 | 全量用户 | 强制更新（P0 系统通知） |
| 版本更新（推荐） | 新版本发布且兼容旧版 | 全量用户 | 推荐更新（P2 运营推送） |
| 活动通知 | 平台活动上线 | 全量/定向用户 | 征文活动、打卡挑战赛 |
| 举报反馈 | 举报处理结果 | 举报发起者 | 举报内容已处理 |
| 勋章解锁 | 用户解锁新勋章 | 勋章获得者 | 解锁"城市探索者"勋章（P1） |
| 勋章进度里程碑 | 勋章进度达到 50%/80% | 勋章进度用户 | 打卡进度达 80%，即将解锁勋章（P1） |

> **勋章推送延迟说明**：勋章解锁推送延迟 5 秒发送（避免与 App 内解锁动画冲突，确保用户先看到动画再收到通知）。

> **AI 助手相关推送说明**：AI 助手对话功能为 P1 优先级，其相关的推送通知（如 AI 规划完成提醒、AI 建议更新等）统一标注为 P1，在 P0 阶段不触发。

### 2.2 互动通知（Interaction Notification）

互动通知属于社交类消息，用户可在设置中按子类型分别开关。

| 子类型 | 触发条件 | 推送对象 | 优先级 |
|--------|----------|----------|--------|
| 点赞 | 用户发布的路线/笔记/评论被点赞 | 内容作者 | P1 |
| 评论 | 用户发布的路线/笔记收到评论 | 内容作者 | P1 |
| 回复 | 用户的评论被回复 | 评论作者 | P1 |
| 关注 | 被其他用户关注 | 被关注者 | P1 |
| 收藏 | 用户发布的路线/笔记被收藏 | 内容作者 | P1 |
| 避雷有用 | 用户发布的避雷信息被标记为有用 | 信息发布者 | P1 |
| @提及 | 在其他用户的内容中被 @提及 | 被提及用户 | P1 |
| 评论点赞 | 用户的评论被点赞 | 评论作者 | P1 |
| 问答新提问 | 攻略收到新提问 | 攻略发布者/内容团队 | P2 |
| 问答被回答 | 提问被回答 | 提问者 | P1 |

### 2.3 行程提醒（Trip Reminder）

行程提醒属于强时效性消息，为 P0 优先级。**P0 推送白名单**：仅当用户主动开启行程且行程时间在未来 24h 内时，行程提醒才在免打扰期间强制推送；否则并入免打扰队列（次日 08:00 后补推），避免凌晨红眼航班等场景吵醒用户。账号安全类 P0 不受此限制，任何时候强制推送。

| 子类型 | 触发条件 | 推送时机 | 优先级 |
|--------|----------|----------|--------|
| 出发提醒（前一天） | 行程开始前 24 小时 | 行程开始日的前一天 20:00 | P0 |
| 出发提醒（两小时） | 行程开始前 2 小时 | 行程开始前 2 小时 | P0 |
| 打卡提醒 | 用户进入打卡地 500 米范围内 | 实时检测，即时推送 | P0 |
| 未完成提醒 | 行程结束日期已过且仍有未打卡点 | 行程结束后次日 10:00 | P1 |
| 行程即将过期 | 行程最后一天当天 09:00 | 当日 09:00 | P0 |
| 行程邀请 | 被邀请加入协作行程 | 实时 | P0 |

### 2.4 运营推送（Marketing Push）

运营推送属于非必要消息，用户可在设置中全部关闭。

| 子类型 | 触发条件 | 推送策略 | 优先级 |
|--------|----------|----------|--------|
| 热门内容推荐 | 算法判断内容热度达到阈值 | 每日 12:00 / 20:00 批量推送 | P2 |
| 本地活动 | 用户所在城市有文旅活动 | 活动开始前 3 天推送 | P2 |
| 个性化推荐 | 基于用户兴趣标签匹配 | 每周推送 1-2 次 | P2 |
| 旅行灵感 | 季节/节假日主题推荐 | 节假日前 1 周推送 | P2 |
| 回流唤醒 | 连续 7 天未打开 App | 第 7 天 10:00 推送 | P2 |

## 三、推送频率控制

### 3.1 单用户每日推送上限

| 指标 | 默认值 | 可配置范围 | 说明 |
|------|--------|------------|------|
| 每日总推送上限 | 10 条 | 5-20 条 | 用户可在设置中调整，P0 消息不计入此上限 |
| 每日运营推送上限 | 3 条 | 1-5 条 | 运营推送单独计数 |
| 每日互动通知上限 | 受总上限约束 | 聚合后计为 1 条 | 不单独设限，受每日总推送上限约束 |

> **重要说明**：P0 优先级消息（行程提醒、账号安全）不计入每日推送上限，任何时候均强制推送。日上限仅对 P1 和 P2 消息生效。

### 3.2 同类型推送聚合策略

| 推送类型 | 聚合窗口 | 聚合方式 | 聚合文案示例 |
|----------|----------|----------|-------------|
| 点赞 | 30 分钟 | 多人聚合 | "张三等 5 人赞了你的路线" |
| 评论 | 30 分钟 | 多人聚合 | "李四等 3 人评论了你的笔记" |
| 评论点赞 | 30 分钟 | 多人聚合 | "张三等 3 人赞了你的评论" |
| 关注 | 30 分钟 | 多人聚合 | "王五等 2 人关注了你" |
| 收藏 | 30 分钟 | 多人聚合 | "赵六等 3 人收藏了你的路线" |
| 避雷有用 | 60 分钟 | 多人聚合 | "你的避雷信息被 10 人标记为有用" |
| 系统通知 | 即时 | 不聚合 | 每条独立推送 |
| 行程提醒 | 即时 | 不聚合 | 每条独立推送 |
| 运营推送 | 按小时 | 批量聚合 | 按小时批量统一推送 |

### 3.3 免打扰时段

| 配置项 | 默认值 | 用户可调 | 说明 |
|--------|--------|----------|------|
| 免打扰开始时间 | 22:00 | 可调 | 默认为晚上 10 点 |
| 免打扰结束时间 | 08:00 | 可调 | 默认为早上 8 点 |
| 免打扰期间 P0 消息 | 条件强制推送 | 不可关闭 | 账号安全强制推送；行程提醒仅当用户主动开启行程且行程时间在未来 24h 内才强制推送，否则排队（P0 白名单，见 2.3） |
| 免打扰期间 P1 消息 | 排队缓存 | -- | 免打扰结束后批量推送 |
| 免打扰期间 P2 消息 | 排队缓存 | -- | 免打扰结束后批量推送 |

### 3.4 防骚扰保护

| 机制 | 规则 | 触发后果 |
|------|------|----------|
| 每日超限 | 单用户推送超过日上限 | 自动降级为消息中心红点，不弹通知 |
| 连续关闭 | 连续 3 次推送被用户关闭通知权限 | 减少该类型推送频率 50% |
| 卸载重装 | 基于设备 ID 在 30 天内重新注册判断 | 默认关闭运营推送，仅保留系统通知 |
| 静默推送 | 用户连续 7 天未点击任何推送 | 自动降级为静默推送（仅更新角标） |

## 五、推送优先级

### 5.1 优先级定义

| 优先级 | 等级 | 推送策略 | 免打扰期间行为 | 适用场景 |
|--------|------|----------|----------------|----------|
| P0 | 紧急 | 立即推送，不使用聚合 | 不受免打扰限制，强制推送 | 行程提醒、账号安全 |
| P1 | 重要 | 5 分钟内推送，支持聚合 | 免打扰结束后批量推送 | 互动通知、审核结果 |
| P2 | 普通 | 按小时批量聚合推送 | 免打扰结束后批量推送 | 运营推送、推荐更新 |

### 5.2 优先级路由逻辑

```
消息产生
  |
  +-- 检查用户推送开关
  |     |
  |     +-- 已关闭 --> 仅写入消息中心，不推送
  |     |
  |     +-- 已开启 --> 判断优先级
  |           |
  |           +-- P0 --> 立即推送（无视免打扰、无视日上限）
  |           |
  |           +-- P1 --> 检查免打扰时段
  |           |     |
  |           |     +-- 免打扰中 --> 加入排队队列
  |           |     +-- 非免打扰 --> 检查日上限
  |           |           |
  |           |           +-- 未超限 --> 聚合窗口内合并后推送
  |           |           +-- 已超限 --> 仅写入消息中心
  |           |
  |           +-- P2 --> 检查免打扰时段
  |                 |
  |                 +-- 免打扰中 --> 加入排队队列
  |                 +-- 非免打扰 --> 检查日上限和运营上限
  |                       |
  |                       +-- 未超限 --> 按小时批量推送
  |                       +-- 已超限 --> 仅写入消息中心
```

### 5.3 排队队列处理

- 免打扰结束时，排队队列中的消息按优先级排序后批量推送
- P1 消息优先于 P2 消息推送
- 同优先级消息按时间先后顺序推送
- 单次批量推送最多 3 条，超出部分延后 5 分钟再次推送

## 六、iOS/Android 推送适配

### 6.1 iOS APNs 配置

| 配置项 | 说明 |
|--------|------|
| 认证方式 | Token-based (P8 文件) + Certificate-based (P12 文件) 双通道 |
| 推送类型 | Alert（通知推送）+ Background（静默推送） |
| 环境 | 开发环境（sandbox）+ 生产环境（production） |
| 有效期 | APNs JWT Token 有效期 24 小时，后端定时刷新 |

**iOS 通知推送（Alert）**：

```json
{
  "aps": {
    "alert": {
      "title": "寻旅记",
      "subtitle": "行程提醒",
      "body": "明天出发！「武汉一日游」准备好了吗？"
    },
    "sound": "default",
    "badge": 5,
    "category": "TRIP_REMINDER",
    "mutable-content": 1
  },
  "type": "trip_reminder",
  "trip_id": "123456",
  "priority": "P0"
}
```

**iOS 静默推送（Background）**：

```json
{
  "aps": {
    "content-available": 1,
    "badge": 5
  },
  "type": "silent_data_sync",
  "action": "refresh_messages"
}
```

### 6.2 Android FCM / 厂商通道

| 通道 | 适用机型 | 接入方式 | 优先级 |
|------|----------|----------|--------|
| FCM | 海外版 / 原生 Android | Firebase SDK | 默认通道 |
| 华为推送 | 华为 / 荣耀 | HMS Push Kit | 国内首选 |
| 小米推送 | 小米 / Redmi | MiPush SDK | 国内次选 |
| OPPO 推送 | OPPO / Realme | OPPO Push SDK | 国内三选 |
| vivo 推送 | vivo / iQOO | vivo Push SDK | 国内四选 |

**Android 通知通道分类**：

| 通道 ID | 通道名称 | 重要度 | 行为 |
|----------|----------|--------|------|
| `trip_reminder` | 行程提醒 | IMPORTANCE_HIGH | 声音+震动+弹窗 |
| `account_security` | 账号安全 | IMPORTANCE_HIGH | 声音+震动+弹窗 |
| `interaction` | 互动通知 | IMPORTANCE_DEFAULT | 声音 |
| `system_notice` | 系统通知 | IMPORTANCE_DEFAULT | 声音 |
| `marketing` | 运营推送 | IMPORTANCE_LOW | 无声，仅通知栏 |

### 6.3 微信小程序订阅消息

| 模板类型 | 模板 ID | 订阅时机 | 一次性/长期 |
|----------|---------|----------|-------------|
| 行程提醒 | 待申请 | 创建行程时 | 一次性 |
| 打卡提醒 | 待申请 | 加入行程时 | 一次性 |
| 互动通知 | 待申请 | 发布内容时 | 一次性 |
| 审核结果 | 待申请 | 提交审核时 | 一次性 |

微信小程序订阅消息限制：
- 每次订阅仅允许推送 1 次
- 用户每次操作需重新授权
- 模板需在小程序后台申请审核

### 6.4 长连接降级方案

当厂商通道不可用时（如 App 被杀死、厂商通道注册失败），使用 WebSocket 长连接作为兜底推送通道。优先级：厂商通道 > FCM > WebSocket > 轮询。

## 八、推送数据埋点

### 8.1 埋点事件

| 事件名称 | 触发时机 | 关键参数 |
|----------|----------|----------|
| `push_send` | 推送已发送 | push_id, type, priority, channel |
| `push_arrive` | 推送到达设备 | push_id, channel, arrive_time |
| `push_click` | 用户点击推送 | push_id, click_time, from_page |
| `push_dismiss` | 用户手动关闭推送 | push_id, dismiss_time |
| `push_setting_change` | 用户修改推送设置 | setting_key, old_value, new_value |
| `push_daily_limit` | 触发日推送上限 | user_id, push_count, limit_type |

### 8.2 核心指标

| 指标 | 计算方式 | 目标值 |
|------|----------|--------|
| 推送到达率 | arrive_count / send_count | ≥ 95% |
| 推送点击率 | click_count / arrive_count | ≥ 8% |
| 推送关闭率 | dismiss_count / arrive_count | ≤ 15% |
| 通知权限开启率 | 已开启用户 / 活跃用户 | ≥ 70% |
| 免打扰开启率 | 已开启用户 / 活跃用户 | 不限 |

## 附录

### A. 推送平台技术选型

| 方案 | 优点 | 缺点 | 推荐 |
|------|------|------|------|
| 自建推送服务 | 完全可控、无第三方依赖 | 开发成本高、通道覆盖不全 | 初期不推荐 |
| 极光推送 | 通道覆盖全、文档完善 | 免费版有量级限制 | 推荐 |
| 个推 | 厂商通道覆盖好 | 价格较高 | 备选 |
| 腾讯云 TPNS | 与微信生态打通好 | 非腾讯系机型覆盖一般 | 适合小程序 |

**推荐方案**：初期使用极光推送（JPush）作为统一推送平台，后续根据业务量级评估是否迁移至自建服务。
