# 21_管理后台设计文档

> **版本**: v2.1.7 | **日期**: 2026-06-26 | **状态**: 新增

---

## 一、概述

管理后台是寻旅记平台运营的核心工具，面向审核员（reviewer）、运营管理员（operator）和管理员（admin）三类角色，提供内容审核、用户管理、CPS 订单管理、数据看板和配置中心等功能模块。

### 1.1 角色与权限

| 角色 | 权限范围 |
|------|---------|
| 审核员（reviewer） | 内容审核、举报处理 |
| 运营管理员（operator） | 用户管理、CPS 管理、数据看板、配置中心、任命审核员 |
| 管理员（admin） | 全部权限，含角色管理、系统配置 |

### 1.2 技术选型

| 项目 | 选择 | 说明 |
|------|------|------|
| 前端框架 | React 18 + Ant Design 5 | 成熟的管理后台 UI 方案 |
| 后端 | Go + Gin（与主服务共用） | 复用现有 API 框架 |
| 权限控制 | RBAC（role + user_role） | 详见 20_权限角色设计.md |
| 部署 | 独立子域名 `admin.xunlvji.com` | 与用户端域名隔离 |

## 二、内容审核管理

### 2.1 审核队列

审核队列展示所有待审核内容，按优先级排序。

| 字段 | 说明 |
|------|------|
| 内容类型 | 打卡记录（checkin_record）/ 打卡地（place）/ 路线（route）/ 攻略（guide）/ 评论（comment） |
| 提交时间 | 内容提交时间，越早越优先 |
| 信用分 | 发布者信用分，低分内容优先审核 |
| 被举报次数 | 已收到举报的内容优先审核 |
| 优先级 | 系统自动计算：高（信用分<80 或 被举报>3）/ 中 / 低（信用分>=90） |

**审核操作（P1-13 审核员权限收窄 + 处罚复核）**：

> 审核员（reviewer）仅可执行「通过 / 驳回 / 建议处罚」三类操作，**不直接扣减信用分、不直接封禁用户**。扣信用分 ≥ 10、禁言、封禁等实质处罚须由运营管理员（operator）二次确认后生效，避免审核员单方面重罚造成误伤。

| 操作 | 执行角色 | 说明 |
|------|----------|------|
| 通过 | 审核员 | 内容发布上线，更新 credit_score（+5） |
| 驳回 | 审核员 | 填写驳回原因，通知用户修改后重提，信用分不变 |
| 建议处罚 | 审核员 | 标记违规，内容立即下架；填写处罚建议（建议扣分值/禁言天数等），提交运营管理员复核，**不直接生效** |
| 批量通过 | 审核员 | 勾选多条内容，一键通过 |
| 批量驳回 | 审核员 | 勾选多条内容，统一填写驳回原因 |
| 复核处罚 | 运营管理员 | 对审核员提交的「建议处罚」二次确认：通过则按建议执行扣分/禁言；驳回则撤销处罚（内容恢复或维持下架由运营判定） |

**处罚复核规则**：
- 扣信用分 ≥ 10 的建议处罚、禁言、封禁用户操作，**必须经运营管理员二次确认**才生效；扣分 < 10 的轻微处理（如内容驳回）审核员可直接执行。
- 建议处罚提交后进入「待复核」队列，运营管理员在工作时间（9:00-22:00）2 小时内复核，非工作时间次日 12:00 前复核；超时未复核则自动驳回处罚建议（内容维持下架状态，但不执行扣分/封禁）。
- 复核结果通知审核员与被处罚用户；被处罚用户可走 3.3 申诉流程。

### 2.2 审核记录

| 字段 | 说明 |
|------|------|
| 内容 ID | 被审核内容的唯一标识 |
| 审核员 | 执行审核的操作员 |
| 审核结果 | 通过 / 驳回 / 建议处罚 |
| 处罚建议 | 建议处罚时填写：建议扣分值 / 禁言天数 / 是否建议封禁 |
| 复核状态 | 无需复核 / 待复核 / 复核通过 / 复核驳回（仅建议处罚需复核） |
| 复核人 | 运营管理员（执行二次确认的操作员） |
| 复核时间 | 二次确认操作时间戳 |
| 审核时间 | 审核员操作时间戳 |
| 审核备注 | 驳回或建议处罚时填写的原因 |
| 操作日志 | 完整操作链路（提交 -> 初审 -> 建议处罚 -> 复核 -> 终审） |

### 2.3 AI 辅助审核

- 内容提交后自动触发 AI 审核（豆包 API），检测违规文本和图片内容。
- AI 审核通过（score >= 0.8）+ 信用分 >= 90 的用户：自动免审发布。
- AI 审核通过 + 信用分 80-89：快速过审通道，30 分钟内人工确认。
- AI 审核通过 + 信用分 70-79：抽审（按比例抽检）。
- AI 审核通过 + 信用分 60-69：强制审核，进入人工审核队列。
- 信用分 < 60：禁止发布，返回错误码 `3007`。
- AI 审核不通过：自动进入人工审核队列，标注 AI 审核结果和风险点。
- 新用户发布数 < 3 时，内容强制进入人工审核队列，不经过 AI 自动审核。

## 三、举报处理中心

### 3.1 举报列表

| 字段 | 说明 |
|------|------|
| 举报 ID | 举报唯一标识 |
| 被举报内容 | 内容类型 + 内容 ID + 内容摘要 |
| 举报人 | 举报用户 ID + 昵称 |
| 举报原因 | 违规 / 不实信息 / 抄袭 / 恶意避雷 / 其他 |
| 举报时间 | 提交时间 |
| 状态 | 待处理 / 已处理 / 驳回举报 |
| 处理人 | 处理该举报的审核员 |

### 3.2 举报处理流程

1. 用户提交举报，系统自动记录举报信息。
2. 举报进入审核员处理队列。
3. 审核员查看举报内容，核实举报原因：
   - 举报属实：审核员对违规内容执行下架，并提交「建议处罚」（扣分/禁言等）；扣信用分 ≥ 10 及封禁须运营管理员二次确认后生效（见 2.1）。举报人信用分 +5。
   - 举报不实：驳回举报，被举报内容不受影响。
4. 处理结果通知举报人和被举报人。
5. 被举报用户可在 7 天内提起申诉，申诉由运营管理员处理。

### 3.3 申诉处理

| 字段 | 说明 |
|------|------|
| 申诉 ID | 申诉唯一标识 |
| 申诉人 | 用户 ID + 昵称 |
| 关联举报 | 原始举报 ID |
| 申诉原因 | 用户填写的申诉理由 |
| 申诉时间 | 提交时间 |
| 处理结果 | 撤销处罚 / 维持原判 |
| 处理人 | 运营管理员 |
| 处理时间 | 操作时间戳 |

## 四、用户管理

### 4.1 用户查询

| 搜索条件 | 说明 |
|---------|------|
| 用户 ID | 精确搜索 |
| 手机号 | 脱敏搜索（仅显示后 4 位匹配） |
| 昵称 | 模糊搜索 |
| 注册时间 | 时间范围筛选 |
| 状态 | 正常 / 禁用 / 注销 |
| 信用分 | 分数范围筛选 |
| 角色 | 普通用户 / 创作者 / 审核员 / 运营管理员 / 管理员 |

### 4.2 用户详情

| 展示信息 | 说明 |
|---------|------|
| 基本信息 | 头像、昵称、手机号（脱敏）、注册时间 |
| 信用分 | 当前分数 + 分数变化历史 |
| 角色 | 当前角色 + 角色变更历史 |
| 内容统计 | 发布数、打卡数、行程数、粉丝数、关注数 |
| 违规记录 | 违规次数、违规类型、最近违规时间 |
| 操作日志 | 封禁/解封记录、角色变更记录 |

### 4.3 封禁与解封

> 封禁属实质处罚，须由运营管理员（operator）执行或对审核员的「建议封禁」二次确认后生效（见 2.1 处罚复核规则），审核员不可直接封禁用户。

| 操作 | 说明 |
|------|------|
| 封禁 | 运营管理员设置封禁原因、封禁时长（1天/7天/30天/永久），封禁后用户不可发布内容和互动；需 2FA 二次确认（见 8.3） |
| 解封 | 手动解封或封禁时长到期自动解封 |
| 批量封禁 | 勾选多个用户，统一封禁（用于批量处理违规账号）；需 2FA 二次确认 |
| 封禁记录 | 完整记录封禁/解封操作的时间、操作人、原因、复核链路 |

## 八、权限与安全

### 8.1 登录安全

- 管理后台仅支持账号密码登录，不支持第三方登录。
- 强制双因素认证（2FA），使用 TOTP 验证码。
- 登录失败 5 次后锁定账号 30 分钟。
- 会话超时：30 分钟无操作自动登出。

### 8.2 操作日志

所有管理后台操作均记录操作日志，包括：

| 字段 | 说明 |
|------|------|
| 操作人 | 操作员 ID + 角色 |
| 操作时间 | 操作时间戳 |
| 操作类型 | 审核 / 封禁 / 配置修改 / 数据导出等 |
| 操作对象 | 被操作的内容/用户/配置 ID |
| 操作详情 | 操作前后的字段变化（JSON diff） |
| IP 地址 | 操作人 IP |

### 8.3 敏感操作二次确认

| 操作 | 是否需二次确认 | 确认方式 |
|------|---------------|---------|
| 扣减信用分 ≥ 10（含审核员「建议处罚」复核） | 是 | 运营管理员复核确认 + 2FA 验证码（见 2.1） |
| 禁言用户（3 天及以上） | 是 | 运营管理员复核确认 + 2FA 验证码 |
| 封禁用户（1天/7天/30天） | 是 | 运营管理员操作 + 2FA 验证码 |
| 永久封禁用户 | 是 | 输入操作理由 + 2FA 验证码 |
| 批量删除内容 | 是 | 输入确认文本 + 2FA 验证码 |
| 修改系统配置 | 是 | 2FA 验证码 |
| 导出用户数据 | 是 | 输入操作理由 |
| 修改佣金结算 | 是 | 2FA 验证码 + 主管审批 |

> 说明：扣信用分 < 10 的轻微处理（如内容驳回）审核员可直接执行，无需二次确认；扣分 ≥ 10、禁言、封禁等实质处罚均须运营管理员二次确认，确保处罚审慎、可追溯（见 2.1 处罚复核规则）。

### 11.2 创作者认证审核

面向运营管理员，管理创作者认证申请与认证标识。

**申请列表**：

| 字段 | 说明 |
|------|------|
| 申请 ID | 申请唯一标识 |
| 申请人 | 用户 ID + 昵称 |
| 申请类型 | 个人认证 / 机构认证 |
| 认证领域 | 美食 / 景点 / 户外 / 住宿 / 综合等 |
| 提交材料 | 身份证明、作品链接、粉丝量证明等 |
| 申请时间 | 提交时间 |
| 审核状态 | 待审核 / 已通过 / 已驳回 |
| 审核人 | 处理该申请的运营管理员 |

**审核流程**：
1. 创作者在用户端提交认证申请及材料。
2. 申请进入运营管理员审核队列。
3. 运营管理员核实材料：
   - 通过：授予认证标识，通知创作者，创作者获得专属模板等权益。
   - 驳回：填写驳回原因，通知创作者补充材料后重新申请。
4. 审核结果记录留存，支持申诉。

**认证标识管理**：

| 操作 | 说明 |
|------|------|
| 标识列表 | 展示所有认证标识类型（名称、图标、权益、状态） |
| 新增标识 | 配置新的认证标识类型 |
| 撤销认证 | 对违规创作者撤销认证标识，需 2FA 二次确认 |
| 变更记录 | 认证授予/撤销的完整操作记录 |

### 11.3 CPS 订单回调

承接第三方 CPS 平台订单回调，统一入库与对账。

> 决策更新（v2.1.7，老板确认）：**P0 只接高德打车 + 饿了么**（2 家，无需企业资质）；携程 + 美团推至 P1（需企业资质）。

**回调接口**：

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 携程回调 | POST | /api/cps/callback/ctrip | 携程订单状态回调（P1 阶段启用） |
| 美团回调 | POST | /api/cps/callback/meituan | 美团订单状态回调（P1 阶段启用） |
| 饿了么回调 | POST | /api/cps/callback/eleme | 饿了么订单状态回调 |
| 高德回调 | POST | /api/cps/callback/amap | 高德打车订单状态回调 |
| 预留回调 | POST | /api/cps/callback/:channel | 未对接渠道预留位置，资质就绪后启用 |

**回调处理流程**：
1. 第三方平台推送订单状态变更（已创建/已支付/已完成/已退款/已取消）。
2. 系统验签后入库，更新订单状态与预计佣金。
3. 异常订单（验签失败、金额异常、重复回调）标记为待处理，人工介入。

**对账管理**：

| 功能 | 说明 |
|------|------|
| 自动对账 | 每日拉取第三方订单数据与本地订单比对，标记差异 |
| 对账报表 | 按平台、按日期生成对账报表，展示一致/差异订单数 |
| 差异处理 | 差异订单进入人工处理队列，运营管理员核实后调整 |
| 佣金核对 | 对账通过后佣金进入结算流程（见 5.2 佣金结算） |
